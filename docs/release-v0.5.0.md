# v0.5.0 — 长文本优化提速 + opencode 会话头兜底 + 解析与路由健壮性修复

本版针对三类实际问题:①长草稿点击优化后等待过久(瓶颈在模型生成输出 token 的数量——默认完整模式每轮要生成「诊断分析 + 优化稿」两段);②opencode(`opencode-go`)模型偶发「缺少请求头」;③一轮代码审查中定位出的若干正确性与健壮性缺陷(标记脚手架曾可能被当结果交付、请求体为 `null` 时端点挂死等)。兼容面与 v0.4.0 一致(同一份构建覆盖 dsh 0.1.0-rc.7 ~ 0.2.0 全线)。

## 主要变更

### 提速与输出顺序(#11)

- **默认优化模式改为快速(仅优化稿)**:快速模式只生成优化结果、不再先生成一段诊断分析,输出 token 与等待时间约减半;想看五维诊断在设置页切回「完整」。已显式保存过 `mode` 的旧设置不受影响。
- **完整模式输出顺序改为「先优化稿、后分析」**:最关心的交付物先流式到达,等待期即可复制取走,分析随后补上。解析层重写为**与标记顺序无关**的段落规则(段落 = 标记到下一个标记/首个 END),新旧两种输出顺序都能正确解析;END 之后的内容视为尾部杂音,不归属任何段落。
- **长度纪律收紧**:简单任务的优化稿目标从 800 字符内收紧到 **500 字符内**,并明确「优化稿就是提示词本身——不复述原稿、不加多余解释或前言」;保真自检仍优先于长度。
- **修复流式预览的一处冻结丢失**:旧版缓冲压缩在 OPTIMIZED 确认后,后续帧会把已定格的分析段清空;现在冻结字段只在首次产出时采纳,且新增优化稿段冻结(新顺序下 ANALYSIS 确认即优化稿定格,缓冲收缩为分析段尾部窗口)。

### opencode 会话头兜底(#11)

- v0.4.0 的会话标注依赖客户端携带会话 id,个别宿主形态不向槽位组件投递 `sessionId` 时请求体缺失、opencode 依旧报「缺少请求头」。0.5.0 起 Host 侧兜底——客户端未携带(或为空白)时标注合成 id `prompt-optimizer-one-shot`,任何调用路径都满足 `x-opencode-session` 要求;客户端正常携带时仍用真实会话 id(会话级计量归属不变)。

### 解析正确性:标记与思考碎片不再进入结果(#12)

- **标记字样绝不进入用户可见结果**:修复两条入口。① 模型写完 `<<<OPTIMIZED>>>` 就直接跳 `<<<ANALYSIS>>>` 时,解析兜底会退回**整段含标记的原文**,且旧判定仍报 `wellFormed: true`(既交付错误内容又无警示),点「替换输入框」会把脚手架粘进输入框;② 模型只吐一个孤立的 `<<<END>>>`(截断/格式跑偏)时会落进「无标记 = 整段即结果」分支被当正文。现改为:有标记时空段落保持为空、优化稿为空即判格式退化,无标记分支先剔除标记字样再判定。
- **未闭合 `<think>` 不再污染解析**:推理中途被 max-tokens 截断时,思考块里复述的标记会锚定成「最后一组标记」,把推理碎片当优化结果交付(而流式预览此时为空)。现丢弃未闭合思考块之后的全部内容。
- **单个损坏的 SSE 帧不再毁掉整次优化**:帧解析无容错,一次代理截断就让已收到的内容全部作废。现跳过坏帧并告警,继续读流。
- **`retry` 保留斜杠命令前缀**:`last.text` 只存拆分后的正文,「重新优化」会丢掉 `/goal` 等命令词,随后的「替换输入框」写回的草稿也缺前缀。现拼回前缀重跑。

### Host 路由健壮性(#13)

- **修复 `JSON null` 请求体导致请求永久挂死**:`readJsonBody` 对 `null` 返回 `null`,与「解析失败已应答」混同后既不写状态码也不 `end`,客户端只能等看门狗超时。现于解析处直接拒绝非对象载荷(`null`/标量/数组)→ 400。
- **修复 SSE 阶段错误逃出路由**:`res.write` 抛错(客户端中途断连)后外层 catch 仍会二次 `writeHead`,抛 `ERR_HTTP_HEADERS_SENT` 成为未处理的 promise rejection。`writeJson` 现按 `headersSent`/`writableEnded` 静默跳过。
- **优化端点新增并发上限**:每次优化都是真实计费调用,而端点本身不限并发(同源多标签页/本机任意进程可刷)。现同时最多 3 个在途,超出直接 `429`;计数在 `try/finally` 配对释放,提前 `return` 的路径也不泄漏。
- **新增 SSE 心跳**:推理模型首 token 前可能几十秒无字节,经反代/隧道(LAN 暴露是 README 声明支持的用法)会被空闲超时掐断。现每 15 秒发送注释帧 `: ping`(客户端解析器只认 `data:` 行,天然忽略)。
- **最低推理档改为按强度序数选取**:旧实现匹配不到关键词就取 `efforts[0]`,假设「首位即最低档」;适配器把高档排在前面时会反向钳到最慢最贵的一档。现按可读出的强度序数取最小档,读不出序数(不透明 id)则回退会话值。
- 另:非法枚举值告警的去重集合改为实例级(热重载后告警可再次出现);路由挂载状态改为随 effect 生命周期复位(载体服务 `dispose→re-register` 后能重挂,且不会重复注册)。

### UI 与文档(#14)

- **结果面板无障碍语义修正**:`role="dialog"` → `"region"`(它是非模态 dock,不抢焦点、无焦点陷阱,`dialog` 会让读屏用户期待并不存在的焦点管理)。
- **设置页底部接回 GitHub 仓库入口**:`GitHubIcon` 组件、`.dsh-po-repo-link` 样式与 `settings.repoTitle` 文案此前都已存在但无人引用(死代码),而 README 宣称设置页含该入口;现按承诺渲染,新标签页打开并带 `rel="noreferrer noopener"`。
- **删除 12 个死 i18n 键**;修正中文 README 的开发基线(写 `0.1.5-rc.1`,实际 `sync:types` 与 devDeps 已钉 `0.2.0-rc.2`);修正文档中「设置卡默认收起、可折叠」等**并不存在**的描述;删除失去引用的折叠态截图。

## 验证

- `npm test` **85 例全绿**(smoke 35 + prompt 24 + controller 26);`npm run typecheck` 零错误;CI(ubuntu-latest + macos-latest)在三个修复 PR 与合并后的 `main` 上均全绿。
- 新增回归用例覆盖本轮修复的每条路径:空 `OPTIMIZED` 段不回退、标记字样不进入结果、未闭合思考块不污染解析、CJK token 估算覆盖(假名/谚文/扩展 B/全角标点)、损坏 SSE 帧被跳过、retry 保留斜杠前缀、非对象 JSON 体被拒绝、SSE 阶段错误不逃出路由、并发上限与计数释放、载体服务只挂载一次、推理档按强度序数选取。
- 兼容性未变:v0.4.0 的实测矩阵继续有效(0.2.0-rc.2 Web + 官方桌面端、0.1.5-rc.2/0.1.5-rc.1、0.1.2 线、0.1.1-rc.2 及以下)。
- **本版未做新的真实 Harness 端到端实测**:#12~#14 为纯逻辑/Host 路由层修复,以单元测试与 mock 宿主(`test/smoke.mjs` 用真实 cordis `Context`)覆盖。建议升级后在真实 `dsh web` 上确认启动日志只出现**一行** `[dsh-prompt-optimizer] loaded`,以及设置页底部 GitHub 入口正常渲染。

## 升级注意

- **旧 profile 里装的插件(0.3.x 及更早)不含 opencode 修复与上述健壮性修复**:`dsh plugin --profile <profile> list` 确认版本,升级到 0.5.0+ 后重启宿主/刷新页面。
- opencode 会话头注入依赖宿主 0.2.x 线的 pi-ai 适配器(按 `GenerateOptions.sessionId` 注入);0.1.x 宿主的 llm 服务不透传该字段,opencode-go 在其上仍不可用,属宿主限制。
- 优化端点新增并发上限:同一时刻最多 3 个在途优化,超出返回 `429`。正常交互(单次点击)不受影响。

## 安装

```sh
dsh plugin --profile web add @y1x1n/dsh-prompt-optimizer
```

或从 Release 下载 `y1x1n-dsh-prompt-optimizer-0.5.0.tgz` 后本地安装:

```sh
dsh plugin --profile web add ./y1x1n-dsh-prompt-optimizer-0.5.0.tgz
```

**官方桌面端**:完全退出应用,用应用自带 CLI 安装并重启(Windows 示例):

```sh
"E:\Deepseek-Harness\resources\runtime\cli\bin\dsh.cmd" plugin --profile desktop add @y1x1n/dsh-prompt-optimizer
```
